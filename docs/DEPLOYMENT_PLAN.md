# System Architecture Deployment Plan: The Zero-Bot Operating System 🚀
> **แผนผังลำดับขั้นตอนเทคโนโลยี 4 เฟส สำหรับติดตั้งบน Layer 2 Testnet (Arbitrum / Base Sepolia)**
> Protocol Edition: Dynamic Global Rebase & Gatekeeper Armor (Version 2.0)

---

## 1. ภาพรวมสถาปัตยกรรม (High-Level Architecture)
ระบบใหม่ตัดตัวช่วย AI หรือบอทตรวจพฤติกรรมหลังบ้านทิ้ง 100% (Zero-Bot Architecture) โดยโอนย้ายตรรกะทั้งหมดขึ้นมาอยู่บน On-Chain Smart Contract ผ่าน 2 เครื่องยนต์หลัก:
- **`TieredRebaseGatekeeper.sol`:** ปรับสัมประสิทธิ์กลาง $globalK$ แบบเรียลไทม์ $O(1)$ วินาทีต่อวินาที พร้อมด่านคัดกรองตัวตน (Proof of Humanity) และจำกัดเพดานความเร็วการโอน (Velocity Limit)
- **`InstitutionalVault3of5.sol`:** คลังสินทรัพย์ค้ำประกันแท้ต้นน้ำ กระจายกุญแจดิจิทัล 5 ดอกข้ามสถาบันสากล

## 2. ลำดับขั้นตอนการติดตั้ง 4 เฟส (4-Phase Deployment Roadmap)

```
┌────────────────────────────────────────────────────────────────────────┐
│  PHASE 1: Core Foundation & Collateral Vault (สัปดาห์ที่ 1)            │
│  - Deploy TVEEToken & TieredRebaseGatekeeper บน L2 Testnet             │
│  - ติดตั้ง InstitutionalVault3of5 และผูกกุญแจพันธมิตร 5 ดอก            │
│  - ฝาก Primary Collateral ทดสอบ (Sepolia ETH)                          │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│  PHASE 2: Gatekeeper & Proof of Humanity Integration (สัปดาห์ที่ 2)    │
│  - เชื่อมต่อ World ID / Gitcoin Passport กับ Gatekeeper ด่านหน้า       │
│  - กำหนดเกณฑ์คุ้มครองรายย่อย (< 100,000 Coins -> globalK = 1.0)       │
│  - เปิดใช้งาน Daily Velocity Limit (50,000 Coins/วัน) สกัด Flash-Mob   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│  PHASE 3: Live Rebase Stress-Testing & Oracle Feeds (สัปดาห์ที่ 3)     │
│  - จำลอง Supply ล้นตลาด (8M -> 12M -> 15M -> 20M Coins)                │
│  - ตรวจสอบการหดตัวของเงินปลาวาฬ (-0.08% ถึง -5%)                       │
│  - ยืนยันว่าเงินของรายย่อยไม่ฝ่อแม้แต่สตางค์เดียว                     │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│  PHASE 4: Community Pilot & Physical Integration (สัปดาห์ที่ 4)        │
│  - ผูกเชื่อมรหัสบัตรขูดนำร่อง (Pilot Batch 20 ใบ)                      │
│  - ทดสอบระบบ Scratch-To-Sync และ 10x Slashing ร่วมกับกระเป๋าจริง        │
│  - เปิดกระดานเทรดเวลา (Time-Token Exchange) ทดสอบรับซื้อตั๋วส่วนลด     │
└────────────────────────────────────────────────────────────────────────┘
```

## 3. ตารางตัวแปรคณิตศาสตร์ของระบบ (Exact System Parameters)

| ตัวแปรในโค้ด | ค่าตัวเลขที่ตั้งไว้ | คำอธิบายความหมาย |
|---|---|---|
| `S_TARGET` | **10,000,000 Coins** | เพดานอุปทานเงินปลอดภัย (จุดที่ยังไม่เกิดภาษีเงินฝ่อ) |
| `S_MAX` | **20,000,000 Coins** | จุดวิกฤตเงินล้นตลาดสูงสุด |
| `MAX_PENALTY` | **5.0% (0.05)** | เพดานการลดขนาดสูงสุดต่อรอบประมวลผล |
| `RETAIL_THRESHOLD` | **100,000 Coins** | เกณฑ์เงินน้อยที่ระบบอุ้มชู 100% เงินไม่ฝ่อ |
| `DAILY_VELOCITY_LIMIT`| **50,000 Coins/วัน** | เพดานการถอนต่อบัญชีต่อวันเพื่อบล็อกบอทฝูง |
| `MULTI_SIG_THRESHOLD` | **3 in 5 Keys** | เกณฑ์เสียงขั้นต่ำในการอนุมัติการเคลื่อนย้ายคลังหลวง |
